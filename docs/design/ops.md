## 1. 错误处理与失败模式

| 情形 | 行为 |
|------|------|
| JSON schema 校验失败 | 拒绝写入，返回错误给 LLM 让它修正；连续 3 次失败则中止并报给用户 |
| 追加式写入检测到原有行丢失 | 拒绝写入并报警（数据损坏级信号） |
| 追加式写入锚点（如 `## 关键事件时间轴`）不存在 | 拒绝写入，**不自动补区段**。区段消失说明文件结构已被破坏，静默补一个空区段会把这个事实藏起来 |
| 工具引用的 ID 不存在 | 拒绝写入，并列出最接近的候选 ID（`C-001` 写成 `C-01` 是最常见的错误形态） |
| 同一工具连续 3 次 schema 校验失败 | 中止并报给用户。连续失败通常是模型理解错了数据结构，第 4 次不会更好 |
| LLM 试图用 `write`/`edit` 写小说根下的文件 | 阻断，告知改用对应的 `novel_*` 工具（见 `data.md「写入护栏」`） |
| 子会话创建失败 | 中止该子任务并报错；**不降级为单会话审查**（否则「3 个独立视角」变成 1 个，用户以为是 3 个） |
| 子会话超时 | 中止并报错，**不静默用部分结果** |
| `submit_findings` 未被调用 | 该审查员记为「未产出」，报告里明示；不假装它审过了 |
| 依据校验全部失败 | 报告标注「本次审查依据普遍无效」，建议用户检查数据层 |
| 模型调用失败 / 重试耗尽 | pi 自身处理重试；扩展层只在 `agent_end` 后检查是否有正文产出 |
| 用户在生成正文中途 Ctrl+C | 状态停在 `outlined`，不落盘半截正文 |
| `/done` 准入不满足 | 拒绝，逐条列出缺什么 |
| 正文写入命中 markdown 标记 | 提示用户确认，不阻断 |
| 小说根目录不存在 / 不是合法小说 | 启动时检测（`isNovelRoot`），提示初始化 |
| `meta.json` 已存在时执行 `/init` | 拒绝并报错。**覆盖一本小说等于抹掉用户全部创作**，不能有「手滑」入口 |
| 核心想法为空时执行 `/init` | 拒绝建书。premise 是一切推断的根，没有它后面全是悬空 |

### 1.1 总原则：失败时绝不静默降级

宁可报错停下，也不要让用户以为某一步做了、其实没做。

**根因**：用户判断是整套流程的最终判据。建立在假信号上的判断会让整套设计失效 —— 用户以为审查跑过了、资料回填了、上下文清空了，于是基于这些前提做决策，而实际上都没有发生。

同一条原则的两个具体落点：

- **未实现的命令也要注册**，敲下去明确提示「计划在里程碑 N 交付」，而不是被当成普通文本交给 AI（见 `interaction.md「命令名的唯一来源与两张表」`）。
- **占位资源不假装可用**：子会话起不来就报错，不退化成单会话。

## 3. 已知限制

| 限制 | 说明 | 影响 |
|------|------|------|
| 同时只能打开一本小说 | `config.json` 只有一个 `novelRoot` | v1 明确非目标；目录结构已为 v2 预留 |
| 无构建步骤 → 不能用 `enum`/`namespace`/构造器参数属性 | Node 类型剥离不做代码生成 | 写这些语法会在运行时直接报错 |
| 护栏可被 shell 绕过 | 只拦 `write`/`edit` 写小说根；用 `bash` 手写 JSON 能绕过去 | **刻意保留**：关掉 shell 的代价大于收益，且绕过需要模型主动绕开一个明确的拒绝提示（见 `data.md「写入护栏」`） |
| 命令必须以 `/` 开头 | 宿主是 pi，输入框是 pi 的编辑器 | 无法做全屏自绘面板 |
| 无热更新 | 扩展是 `extensionFactories` 内联注册的，`/reload` 不重载它 | 改完 `src/` 必须重启进程 |
| 段落编号依赖空行分段 | `chapter#012:para7` 的校验是「段落数 ≥ 7」（尽力而为） | 用户手工编辑打乱空行后，段落引用可能偏移 |
| 里程碑 1 尚无写入工具限制 | 已在里程碑 2 关闭：写入护栏拦 `write`/`edit` 写小说根，错误文本导向 `novel_*` 工具 | 已解决 |
| 默认模型 `deepseek-flash` 写正文质量上限受限 | 见 `ai.md「模型选择」` | 用户可把 `draft` 换成强模型 |

**开发中发现并修正的问题**

| 问题 | 根因 | 处理 |
|------|------|------|
| typebox 的泛型 helper 把 `Static` 推成 `never` | `(...values) => Type.Union(values.map(Type.Literal))` 让 tuple 的字面量信息在 `.map()` 之后丢失，整个对象类型随之不可用 | 放弃 helper，枚举 schema 内联；用「常量列表 ↔ schema 互锁断言」防漂移（见 `decisions.md`） |
| typebox 1.x 默认**允许**额外属性 | 不写 `additionalProperties: false` 就等于放行 LLM 传的任意字段名变体 | 所有对象（含工具参数）显式写 `STRICT`，并加断言覆盖 |
| `readJson` 无法区分「文件不存在」与「文件坏了」 | 原实现 `catch { return null }` 吞掉了一切错误，手改坏的书会显示成「没有这本书」 | 新增 `readJsonFile`：`ENOENT` 返回 null，其余抛错 |
| `appendInbox` 的锚点写成了文件标题 | `inbox.md` 的标题是 `#`（一级），可追加区段是 `## 记录` | 锚点保护直接拒绝了写入并报出可诊断的错误 —— 这正是它该做的 |

**一处主动补上的设计缺口**

`StoryEvent` 新增 `characters` / `settings` 两个字段。原设计里 `events/E-NNN.md` 有「涉及」区段，但索引里没有对应的结构化来源，那段文本只能靠 LLM 手写 —— 而手写的东西不可校验。补上结构化字段后，「涉及」区段由代码从字段渲染。

**里程碑 1 的已知缺口已关闭**

「LLM 可以直接 `write`/`edit` 改 `*.json`」已由写入护栏消掉：`write`/`edit` 写小说根下的任何文件被阻断，错误文本直接把模型导向对应的 `novel_*` 工具。

**一次被自己否决的设计**

护栏最初还额外禁用了 `bash` / `powershell`，理由是「不关这个口子，write/edit 的拦截就是纸糊的」。这个推理把「机制闭合」当成了目的本身：关掉 shell 的代价（AI 不能跑 git、查日志、跑测试）是立刻发生的，而它防的「用 bash 手写 JSON」需要模型主动绕开一个明确的拒绝提示 —— 不是它被拦住后的自然行为。用户指出后已拆掉，并在 `decisions.md「已否决的方案」`里记下，避免重新发明。
